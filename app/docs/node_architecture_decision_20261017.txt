Node architecture decision / 2026-10-17
Type: user-confirmed development scope; implementation and acceptance pending.

用户确认原文：
“接受板内硬件端点，按单板方案完成验收。实体按FPGA处理，虚拟的在arm上。”

1. 总体目标
一块Zynq7020、一台电脑。16个无人机节点由2个PL硬件端点和14个ARM软件虚拟节点组成，另设地面站0。首先实现1个硬件端点和15个虚拟节点作为中间检查点。
保持统一节点编号与业务协议；具体硬件端点ID由接口设计固定，不改变16节点的总数。

2. 分工
PL硬件端点：自己的业务产生、收发缓冲、序号及协议状态、必要确认/重传/去重、命令执行与结果回传。允许共享运算资源，但端点状态独立。
ARM虚拟节点：在PS软件中实现对应节点行为。
ARM系统管理：场景、位置输入、统一模型时间、时隙、路由与共享核心调度、参数管理及上位机交互。
共享PL通信核心：所有节点数据和ACK均通过调制解调、信道、纠错和真实接收处理。
PC：UI、记录、回放、参数操作和用户建议。

3. 验收
a. 停用某硬件节点的ARM软件代发路径，保留系统级模型时钟与调度后，该硬件端点仍能产生自己的业务。
b. 硬件端点与虚拟节点的业务经过实际PL信道，并核对完整接收内容；不以ARM复制发送数据替代接收。
c. 下行命令到达指定端点后由它执行，地面收到执行结果后才显示成功。
d. 单独停用、故障注入或复位硬件端点，能观察失联及恢复，其他节点状态不受错误污染。
e. 新架构重新检查资源、时序、运行时间和整机稳定性；不能直接沿用原16个软件逻辑节点的通过记录。

4. 范围与材料
本轮无需等待第二板或外部设备接入；GPS、实飞、射频均非前置条件。
文稿写“板内FPGA硬件端点+ARM软件虚拟节点”，不写已接入外部无人机或独立硬件终端。
本决定取代开发计划中等待实体节点解释的分支，以及旧端点文档对本轮交付范围的外部设备依赖；历史日志、硬件通过记录与旧协议测试的事实不变。
外部接入协议保留作为未来扩展。用户确认不等于记录到组委会新规则或官方答复。
